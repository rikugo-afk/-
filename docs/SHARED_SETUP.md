# ログインなし・URLで共有するための設定

URLを開いた人が同じ案件を閲覧・編集・削除する構成です。社員アカウント・パスワード・ログインは不要です。URLや公開キーを知っている人に対するアクセス制限はありません。

## すでに社員ログイン版のSQLを実行した場合

1. SupabaseのSQL Editorで新しいクエリーを開きます。
2. `supabase/enable-public-access.sql` の全文を貼り付け、Runを押します。
3. 「URL共有に変更しました。ログインは不要です。」と表示されればDBの切り替えは完了です。
4. アプリの更新をmainへ反映し、GitHub Pagesの公開処理を実行します。

切り替えSQLは読み書きRPCの社員チェックと実行権限だけを変更し、案件・下書き・開発進捗・更新版・採番履歴には変更を加えません。再実行も可能です。以前の関数の形式が異なる場合は途中で止まり、権限を部分適用しません。その場合は現在の `supabase/schema.sql` 全文を実行してください。

この作業にはSupabase管理画面のSQL実行権限が必要です。ブラウザー配信用のPublishable keyでDBの関数・権限を変更することはできません。

## 新規のプロジェクトの場合

1. https://supabase.com/dashboard でプロジェクトを作成します。
2. SQL Editorで `supabase/schema.sql` 全文を実行します。これは最初からログインなしの共有用です。
3. Project URLとPublishable keyを `public-config.json` に設定します。管理用のsecret key・service_role・DBパスワードを入れないでください。
4. GitHub Pagesの公開処理を実行します。

今回のプロジェクトのURLとPublishable keyは設定済みです。SupabaseのUsersやメール送信・リダイレクト設定は、URL共有には使いません。

## 公開と確認

mainへのpushまたはActionsのDeploy Order Desk to GitHub Pagesで、テスト・ビルド・接続チェック・配置を行います。接続チェックは公開キーの有効性だけを確認し、案件データを取得・変更しません。DBの権限設定が未完了の場合は、アプリが接続エラーを表示し、ローカル保存へ自動で切り替えません。

公開URL： https://rikugo-afk.github.io/-/

別々のブラウザーでURLを開き、ログインなしで同じ案件が表示されることを確認します。片方で「編集」→入力→「保存」した内容が、もう片方でも再読み込み・約15秒後・タブ復帰時に表示されます。同じ版を編集中に先に別の利用者が保存した場合、後の保存は競合として止めます。未保存の内容を退避してから最新データを読み込めます。

## 以前のローカルデータの移行

以前のデータがあるブラウザーで公開URLを開きます。共有DBが空なら、バックアップ後に「共有DBへ移行する」を押してください。元のブラウザーデータは削除しません。共有DBがすでに使われている場合は、移行ボタンを無効にして不用意な置き換えを防ぎます。

## 開発時

```sh
npm ci
npm test
npm start
```

`public-config.json` の共有接続を使用します。別プロジェクトを使う場合は `SUPABASE_URL` と `SUPABASE_ANON_KEY` の両方をビルド時に指定します。`ORDER_DESK_MODE=local npm start` で従来のブラウザー内保存も確認できます。`.env` は自動では読み込みません。

## 保存と制約

- 案件・下書き・開発進捗・採番履歴を1つのスナップショットとしてトランザクション保存します。版チェックで同時更新の上書きを防ぎます。
- 匿名のRPC利用を許可します。直接のテーブル操作は拒否し、入力検証と版チェックを通したRPCからだけ案件を変更できます。
- 公開利用には利用者ごとの権限・操作した人の特定・社員別の停止機能はありません。JSONバックアップを定期的に保管してください。
- 通信失敗時は変更を画面に保持し、保存済みとして扱いません。未保存のまま閉じた変更は共有されません。
- 旧社員テーブルは互換性のため保持しますが、URL共有の可否には使用しません。


## 元データの反映と項目追加

元シートの取り込みはREADMEの「元シートの取り込み」を参照してください。実データをソースコードやGitHub Actionsに渡さず、利用者のブラウザーから共有DBへ保存します。項目名・列の追加／削除も同じ共有JSONの中に保存されるため、項目を変更するたびにSQLを実行する必要はありません。
