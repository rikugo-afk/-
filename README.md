# Order Desk — 受注管理

18項目の案件入力、受注管理・受注完了・開発進捗、期間別の売上・粗利集計ができる日本語アプリです。

URLを開いた人がログインせずに同じ案件を閲覧・編集・削除する共有アプリです。[セットアップ手順](docs/SHARED_SETUP.md) に、社員ログイン版からの切り替えとSupabaseの設定を記載しています。

## 起動と検証

Node.js 22以上を使用します。

```sh
npm ci
npm test
npm start
```

既定はポート3000です。変更時は `PORT=3100 npm start` を使用します。`npm start` は静的サイトをビルドしてから開発サーバーを起動します。

`npm test` は集計・入力・並び替え・公開ファイル・HTTP配信の検証に加え、PGlite上のPostgresで共有DBのSQLを実行し、匿名での共有読み書き・旧版からの移行・同時編集の競合・採番履歴を検証します。本番Supabaseへの接続検証はセットアップ後に行ってください。

## 保存モード

| モード | ログインと保存先 |
|---|---|
| ローカル | `ORDER_DESK_MODE=local npm start`。ログインなし。同じブラウザー・同じオリジンのlocalStorageのみ。端末間では共有しません。 |
| URL共有（既定） | ログインなしで同じ共有Postgresの全案件を閲覧・編集・削除します。 |

`public-config.json` に、今回指定されたSupabaseプロジェクトのURLと公開用Publishable keyを設定済みです。既定でURL共有モードをビルドします。公開キーはブラウザーに配信する接続情報です。URLや公開キーは閲覧・編集を制限する秘密情報ではありません。管理用キーやDBパスワードをコードに保存しないでください。

ビルド時の `ORDER_DESK_MODE` でモードを上書きできます。別プロジェクトへ切り替える場合は `SUPABASE_URL` と `SUPABASE_ANON_KEY` の両方を指定します。片方だけの上書きや不正なキーは拒否します。`.env` は自動では読み込みません。

共有データは「保存」を押したときに一括保存します。ほかの利用者の更新は約15秒ごととタブ復帰時に確認します。同じ版を同時編集した場合、後の保存を止め、未保存の内容の退避と最新データの再読込を案内します。通信エラー時も変更は画面に保持します。

ログイン・社員登録は不要です。共有案件のキャッシュはメモリーに保持します。従来のローカルデータは自動でアップロードせず、元データを残して明示的に移行します。

## 公開

```sh
npm run build
```

`dist/` の4ファイル（HTML・ハッシュ付きJS/CSS・`.nojekyll`）を静的ホスティングへ配置します。サブディレクトリでも利用できます。

GitHub Pagesは Settings → Pages → SourceをGitHub Actionsにします。付属の `.github/workflows/pages.yml` はmainへのpushまたは手動実行で、依存インストール・テスト・ビルド・配置を行います。共有モードのGitHub Variables設定は [セットアップ手順](docs/SHARED_SETUP.md) を参照してください。変数を設定しただけでは稼働中の画面は変わりません。

配置前の `npm run check:connection` は公開キーの有効性だけを確認し、案件データをGitHubへ取得しません。DBのアクセス許可・保存・競合保護はSQLテストとブラウザーで検証します。公開後はログイン画面がないHTMLとアプリJSの配信を確認します。

公開URLは https://rikugo-afk.github.io/-/ です。GitHub Pagesと共有案件は誰でもアクセスできます。閲覧・入力・変更・削除に社員認証はありません。開発用Nodeサーバーを公開運用する必要はありません。

## 案件の項目

営業No.、BRK、ステータス、営業担当、記入日、契約予定日（締結日）、案件名、フォルダ、許可証種類、住所、Googleマップ、流入経路、営業売上、コスト、営業粗利、(契)入金日、入金確認、備考。

- 営業担当：藤田・本間・高橋・鈴木・郷・菅原・OS。
- ステータス：面談取り付け・初回面談済・継続面談中・収支シミュ提出・契約交渉中・契約締結予定・契約済・破談。
- 許可証種類：民泊・旅館業。
- 流入経路：問い合わせ（HP）・問い合わせ（電話）・既存オーナー・OS交渉による既存オーナー・新規アプローチ・紹介。
- 金額：0以上の整数。初期値は空欄で、明示的な0円と未入力を区別します。売上・コストの両方が入力されると粗利を自動計算します。
- 日付：`20261105` を入力すると「2026年11月5日」と表示します。存在しない日付は保存しません。
- フォルダ・GoogleマップはHTTP/HTTPSのURLです。入金確認は未選択・未入金・入金済を区別します。

## 直接入力と保存

案件一覧は常に入力用の空行を表示します。「編集」を押してセルに入力し、一覧上部の「保存」で案件・下書き・開発進捗をまとめて確定します。セル移動だけでは保存しません。案件名が入ると案件行になり、次の空行が表示されます。案件名が未入力なら下書きとして保持します。ステータス・記入日が空欄の案件は面談取り付け・当日で補います。

Enter／Tabで次、Shift+Enter／Shift+Tabで前の入力項目へ移動します。矢印キーで上下左右のセルへ移動できます。日本語変換中は移動せず、Shift+矢印は文字選択、備考のShift+Enterは改行です。Escで編集中のセルを元に戻します。

「＋ 行を追加」で空行を追加し、行の「コピー」で内容を複製できます。コピー時は内部ID・営業No.・BRKを新しくし、開発進捗は複製しません。削除時は「本当に削除しますか？」と確認します。詳細画面からも入力できます。共有モードでは詳細画面の変更も一覧の「保存」で確定します。

編集中は元のワークスペースに案件を保持し、保存時に移動します。未保存の変更がある間はワークスペースを切り替えられず、ページを閉じる際も確認します。保存失敗時は編集を継続できます。

## 自動採番

営業No.は行を追加した時点で数字のみの連番を割り当てます。最初の空行・下書き・コピー行も対象です。旧形式 `S-001` は `1` に揃え、重複は後の番号に振り直します。案件IDと開発進捗の紐付けは維持します。

BRKは契約締結予定または契約済になった時点で、800から採番します。案件名を入れる前の下書きも対象です。付いた番号はステータスを戻しても保持します。両番号は直接変更できず、取り消し・削除でも採番履歴を巻き戻しません。

共有モードでは編集中の番号は仮表示です。同時追加は共有保存時の版チェックで重複を防ぎ、競合した側は最新データからやり直します。

## ワークスペース

- 受注管理：受注完了の条件を満たしていない案件。
- 受注完了：備考以外がすべて入力済み、ステータスが契約済、入金確認が入金済の案件。
- 開発進捗：契約済の全案件と、元シートから取り込んだ開発案件。下記の開発項目を直接編集できます。

契約済でも未入力・未入金の案件は受注管理と開発進捗に表示します。受注完了から外れても開発の記録は保持します。移動・復帰の際は案件名・番号と移動先を画面に表示します。

「契約済」の選択には、営業No.・BRK・営業担当・記入日・契約予定日（締結日）・案件名・フォルダ・許可証種類・住所・Googleマップが必要です。BRKがなければ、先に契約締結予定を選んで採番します。

受注完了から項目を空欄にして保存する際は「空欄があります。受注管理に戻しますか？」と確認します。契約済以外・未入金に変更した場合も該当理由で確認します。キャンセル時は未保存のまま編集できます。

## 表示・並び替え・集計

案件一覧・月別売上は開閉できます。案件一覧は最大30行分の高さで、続きは行専用のスクロールバーで確認します。列見出しは一覧内とページ全体のスクロール中も固定し、横方向の位置を同期します。一覧の上下端ではページ全体へホイール操作を引き継ぎます。

各列見出しまたは並び替え選択から昇順・降順を切り替えます。下書きも含む全表示行が対象で、空欄は末尾、番号・金額は数値順、日付は年月日順です。検索・ステータス・入金状況で絞り込めます。

上部の合計と月別売上・粗利は、開始月〜終了月と集計基準（契約日または入金日）に連動します。初期期間は2026年10月〜2027年9月です。`202610` は「2026年10月」と表示し、カレンダーからも選択できます。Enter／右・下矢印で次、Shift+Enter／左・上矢印で前へ移動します。期間は最大10年で、不正な値のときは前の集計を保持します。

集計は現在のワークスペースの全案件が対象です。一覧の検索・絞り込みとは独立し、期間外・基準日未入力の案件は金額に含めず除外件数を表示します。下書きは件数・集計に含めません。会計上の売上認識ではなく、入力された金額の合計です。

## バックアップと取り消し

「元に戻す」は編集中の操作と保存済みの操作に対応します。保存後は保存1回分をまとめて戻します。最大30件をメモリー内に保持し、再読込で履歴は消えます。共有DBへの取り消しも版チェックで保護します。

CSVは現在の一覧の絞り込み・表示順で出力します。「•••」メニューのJSONバックアップは、ローカルモードでは全案件、共有モードでは全案件・下書き・開発進捗・採番履歴を含みます。復元前に置き換え確認を行い、共有データは「保存」で確定します。従来の案件配列形式も読み込めます。ローカルモードのバックアップは開発進捗・下書きを含みません。

共有DBが空の場合、以前のデータが残るブラウザーに移行案内が表示されます。元データのバックアップと明示的な移行が可能です。すでに共有データがある場合は移行ボタンを無効にし、不用意な置き換えを防ぎます。


## 開発進捗の項目・追加・変更

提示された項目の重複を統合し、開発担当・営業担当を分け、契約書・入金を一覧から外した77項目と区切り列を元の順に表示します。進捗・BRK・契約書・入金・施設情報・ベッド内訳・各工程・清掃・設備・売上報告まで入力できます。列見出しからの並び替え、固定見出し、上下・左右スクロール、「項目へ移動」、Enter・矢印での入力移動に対応します。

「編集」中に項目名を入力して「＋ 項目を追加」で列を増やせます。文字・長文・数値・整数・金額・日付から入力形式を選べます。見出しの✎で名前を手入力し、×で列を非表示にできます。削除した列の値は保持し、「削除した項目」から復元できます。列設定も「保存」で全員に共有され、「元に戻す」とJSONバックアップの対象です。

- リードタイム：着手日から公開目標までの暦日差。どちらか未入力なら空欄。
- 粗利：開発売上 − 仕入金額。リネンは仕入金額に含むため二重に差し引きません。
- 粗利率：粗利 ÷ 開発売上 × 100。売上未入力・0円では空欄。

BRKは受注案件から連動します。営業担当は受注管理の営業担当に連動し、この画面では直接変更しません。受注情報がない開発案件の営業担当は空欄です。開発担当は別の手入力欄とし、従来の担当欄への入力や元シートから取り込んだ担当者を保持します。施設名・住所・Googleマップ・許可証種類・入金は案件情報を初期表示し、開発側で変更した値は別に保持します。元データの曖昧な日付やチェック値は文字として保持し、計算から除外します。直接入力する日付は従来どおり8桁にも対応します。

## 元シートの取り込み

「••• → 元データを取り込む」から、変換済みの取り込みJSONを選びます。既存の案件は削除せず、同じBRKまたは元データIDで照合して追加・更新します。営業No.の衝突時は新しい番号を割り当てます。開発進捗にだけある施設は、受注案件を作らず開発データとして保持します。元シートにある開発案件は契約ステータスにかかわらず表示します。

取り込み件数を確認して読み込み、上部の「保存」で共有DBへ反映します。再取り込みで同じ元データを重複登録せず、追加した項目や既存入力を残します。元シートの空欄で既存入力を消しません。通常のJSONバックアップ読込は従来どおり置き換えで、取り込み専用JSONとは区別します。

元の各セル・重複列・未入力のテンプレート行・注記・集計行も、共有バックアップ内の元データとして保持します。CSVでは表示文字しか残らないハイパーリンクは、URLを推測して作りません。年がない単一日付は2026年度（10月〜翌9月）として補完し、範囲・予定・注記を含む文字列は元の文字を保管します。契約済み／初回面談済み等は現在の選択名に揃えます。

開発項目の定義と元データの保管領域は既存の共有JSON内に保存するため、項目追加のための追加SQL実行は不要です。会社の実データはリポジトリにコミットせず、配信用JSにも埋め込みません。

CSVからのローカル変換（外部送信なし）：

```sh
python3 scripts/prepare-source-csv.py --orders ORDERS.csv --development DEVELOPMENT.csv --output /tmp/order-import
```

列の右端をドラッグすると、「編集」を押さずに案件一覧・開発一覧の横幅を変更できます。横幅は各ブラウザーの表示設定として保持し、入力データの保存や取り消しには影響しません。開発一覧の契約書・入金は非表示とし、保存済みの値は保持します。
