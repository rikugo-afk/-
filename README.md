# Order Desk — 受注管理

18項目の案件登録・編集・削除、検索、ステータス／入金絞り込み、売上・粗利・未入金額集計、CSV出力、JSONバックアップ／復元ができる日本語アプリです。営業粗利は「営業売上 − コスト」で自動計算します。金額は円単位の0以上の整数です。許可証種類は「民泊・旅館業」の選択式です。BRKは条件に応じて自動採番します。

## 起動

Node.js 22以上。外部依存のインストールやAPIキーは不要です。

```sh
cd /workspace/-
npm start
```

ポートは既定で3000です。変更する場合は `PORT=3100 npm start` を使用します。

## 検証

```sh
npm test
```

画面の「サンプルデータで試す」から架空の案件3件を登録できます。サンプルは未登録時のみ追加できます。CSVは現在の絞り込み結果、JSONバックアップは全案件を保存します。復元は全データを置き換えるため、確認ダイアログを表示します。

## 保存範囲

データはブラウザーのlocalStorageに保存されます。同じブラウザープロファイル・同じオリジン（ホストとポート）でのみ継続利用でき、サーバーへの案件送信や複数端末での同期はありません。ブラウザーの保存データ削除で失われるため、定期的にJSONバックアップをダウンロードしてください。認証・共有DBは未実装のため、チーム共用には別途バックエンドの追加が必要です。開発サーバーは公開運用向けではありません。

## Web公開

```sh
npm run build
```

`dist/` に静的サイトが生成されます。JSとCSSは内容に応じてファイル名が変わるため、公開後に古いスクリプトが混在することを防ぎます。このフォルダ内の5ファイルだけをHTTPS対応の静的ホスティングに配置します。Node.jsサーバーは公開先で不要です。サブディレクトリへの配置にも対応しています。`index.html` はファイルとして直接開くのではなく、HTTP/HTTPS経由で配信してください。

- Netlify：ビルドコマンド `npm run build`、公開ディレクトリ `dist`。手動配置の場合は生成した `dist` フォルダをアップロードします。
- Vercel：Framework PresetをOther、Build Commandを `npm run build`、Output Directoryを `dist` に設定します。
- GitHub Pages：リポジトリの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選びます。付属の `.github/workflows/pages.yml` がmainへのpush時にテスト・ビルド・公開します。初回に設定を変更した場合は **Actions → Deploy Order Desk to GitHub Pages → Run workflow** を実行します。リポジトリへのpush権限とPages設定権限が必要です。公開URLは成功したActionsのdeployment出力またはPages設定で確認できます。

公開先へのログイン・接続と配置は別途必要です。開発中のブラウザー内データは公開サイトには移行されません。移行する場合は開発画面からJSONバックアップを保存し、公開サイトで読み込んでください。サイト自体には認証がなく、URLを知っている人がアプリ画面を開けます。各利用者の入力案件は引き続きそれぞれのブラウザー内に保存されます。

## 項目

営業No.（一意・必須）、BRK、ステータス、担当者、記入日、契約予定日（締結日）、案件名（必須）、フォルダ（URL）、許可証種類、住所、Googleマップ（URL）、流入経路、営業売上、コスト、営業粗利（自動）、(契)入金日、入金確認、備考。

## 元に戻す

一覧上部の「元に戻す」で、保存済みのセル編集・詳細画面からの保存・行の追加／削除・下書き編集・バックアップ読込を1操作ずつ取り消せます。この画面を開いている間の履歴を最大30操作まで保持します（データ量が大きい場合は保持件数が少なくなります）。再読み込みすると履歴は消えます。検索・期間・開閉などの表示設定は対象外です。自動採番の履歴は戻さず、番号の再利用を防ぎます。

## BRKの自動採番

ステータスが「契約締結予定」または「契約済」で、BRKが空欄の場合に800から自動採番します。既存の数字BRKと採番履歴の最大値に続けて採番します。既存のBRKは保持し、一度付けた番号はステータスを戻しても保持します。BRKは手入力できません。すでに対象ステータスになっている未採番案件も「保存」を押した際に採番します。下書きは案件名を確定して案件として保存された時点で判定します。

## 選択式の項目

ステータスは「面談取り付け・初回面談済・継続面談中・収支シミュ提出・契約交渉中・契約締結予定・契約済・破談」です。新規案件の初期値は「面談取り付け」です。

流入経路は「問い合わせ（HP）・問い合わせ（電話）・既存オーナー・OS交渉による既存オーナー・新規アプローチ・紹介」です。未選択も可能です。



担当者は「藤田・本間・高橋・鈴木・郷・菅原・OS」の選択式です。未選択も可能です。変更前に保存した別の担当者名は保持し、その案件を開いたときに既存値として表示します。

## 一覧での直接入力

案件一覧の見出しをクリックして開閉できます（初期は開いた状態）。開閉状態はブラウザー内に保存されます。閉じても案件データ・下書き・集計は保持されます。

一覧は空行を含め最大30行分の高さで表示し、それ以上は一覧内の縦スクロールで確認できます。列見出しはスクロール中も固定されます。全案件は保持され、集計・検索・CSV出力も全件が対象です。

一覧右上の「編集」を押すと入力モードになります。セルをクリックして変更し、Enterまたは別のセルへの移動で編集内容を一時反映します。「保存」で確定します。Enter／Tabで次の入力項目、Shift+Enter／Shift+Tabで前の項目へ移動します。矢印キーは上下左右のセルへ移動します（営業粗利は自動計算なのでスキップ）。左右は同じ行内、上下は同じ列、Enter／Tabは行末から次の行へ進みます。Shift+矢印は通常の文字選択として利用できます。日本語変換中のEnterでは移動しません。Escで編集中のセルを元に戻せます。備考の改行はShift+Enterです。営業粗利は自動計算のため直接変更できません。一覧の末尾には常に入力用の空行があります。「案件を登録」ボタンはありません。「編集」を押し、空行へ直接入力します。案件名が入力されると編集中の案件行になり、次の空行が表示されます。一覧上部の「保存」で保存を確定します。営業No.は案件名の確定時に `S-001` 形式で自動採番し、編集できません。保存済み番号は保持します。現在の最大番号と保存した採番履歴に続く番号を使用するため、削除した番号は通常再利用しません（ブラウザーの保存データを消去した場合を除く）。ステータス・記入日が空欄の場合は、面談取り付け・当日の日付を設定します。

一覧の下にある「＋ 行を追加」で空行を増やせます（編集モードのみ）。追加後は新しい行の最初の入力項目に移動します。追加した空行は、未入力でもブラウザーに保存されます。

案件名が未入力の情報は「保存」を押すと下書きとしてブラウザーに保存され、再読み込みしても入力を再開できます。空行と下書きは登録件数・売上集計・CSV・JSONバックアップに含めません。バックアップ前に案件名を入力して案件として確定してください。

「保存」で変更を確定して閲覧表示に戻ります。編集モードでは各行の右端に「行を削除」が表示されます。入力済み案件・下書きは確認後に削除します。未入力の空行も「本当に削除しますか？」の確認を挟み、最後の空行を削除した場合は入力用の空行を1行残します。削除に合わせて期間集計も更新されます。各行の「詳細」から全項目をまとめて編集・削除することもできます。不正な金額・URL・重複した営業No.は保存せず、エラーを表示します。セル移動だけではブラウザーへの保存は行いません。一覧上部の「保存」を押してください。

## 月別売上・粗利

月別表は見出しをクリックして開閉できます（初期は閉じた状態）。開閉状態はブラウザーに保存します。閉じても上部カードの集計は更新されます。

画面上部の「開始月〜終了月」に `2026/10` や `2027-09` の形式で手入力し、Enterまたは欄からの移動で反映できます。全角や「2026年10月」形式も入力できます。指定すると、対象案件数・売上・粗利・未入金額の合計と月別表が同じ期間に連動します。開始月の初日〜終了月の末日を含みます。初期値は2026年10月〜2027年9月で、単月から最大10年まで指定できます。期間設定はブラウザー内に保存され、次回も復元します。「初期期間に戻す」で元の期間に戻せます。開始月が終了月より後の場合などはエラーを表示し、直前の有効な集計結果を維持します。初期の集計基準は「契約予定日（締結日）」で、「(契)入金日」にも切り替えられます。日付未入力と期間外の案件は月別表・金額カードに含めず、除外件数を表示します。入力時に売上・コスト・基準日・入金確認を変更すると即座に再集計します。

上部の対象案件数・金額カードはすべて選択した期間・日付基準の合計です。案件一覧は期間にかかわらず全案件を表示します。一覧の検索フィルターは月別集計には影響しません。失注も含む入力済み金額の合計であり、会計上の売上認識ではありません。CSV出力は月別表ではなく、従来どおり一覧の絞り込み結果を出力します。

## ワークスペースと開発進捗

「受注管理」は入力途中の案件、「受注完了」は備考以外の全項目が入力された案件を表示します。営業No.・BRKも判定に含め、粗利は自動計算値を使用します。0円と未入金（入金確認がfalse）も値が入っているものとして扱います。一覧上部の「保存」を押した時に表示先が切り替わり、データ自体は同じ保存領域で保持します。受注完了から項目を空欄に戻す際は「空欄があります。受注管理に戻しますか？」と確認し、キャンセルした場合は保存しません。元に戻す操作で空欄に戻る場合も確認します。各ワークスペースの期間集計は、その画面の案件が対象です。JSONバックアップは全案件を含みます。

「開発進捗」には受注完了案件を自動表示し、開発状況（未着手・進行中・確認待ち・完了）と開発備考を入力できます。案件が受注管理に戻ると開発一覧から外れますが、開発進捗の記録は保持し、再度受注完了した際に復元します。開発進捗の編集も「元に戻す」の対象です。開発進捗はこのブラウザー内に別保存され、現在の案件用JSONバックアップには含まれません。

## 一覧の並び替え

各列の見出しをクリックして昇順・降順を切り替えます。検索後の全件を対象にし、空行・下書きは末尾に残します。空欄は昇順・降順のどちらでも末尾です。番号は数値順、売上・コスト・粗利は金額順、日付は年月日順に並べます。CSVは表示順で出力します。

## 保存で変更を確定する

「編集」を押すと編集モードになり、ボタンが「保存」に変わります。Enter・Tab・セル移動は編集内容の一時反映で、ブラウザーの保存データにはまだ書き込みません。「保存」を押すと、案件・下書き・開発進捗をまとめて保存し、その時点で受注管理／受注完了への移動を判定します。編集中は元の一覧に案件を保持します。受注完了から空欄に戻す確認も保存時に行い、キャンセル時は未保存のまま編集を続けられます。

編集中の「元に戻す」は一時的な変更を取り消し、保存後の「元に戻す」は保存1回分をまとめて戻します。保存前に再読み込みやページを閉じると、未保存の変更は失われるためブラウザーが確認します。未保存の変更がある場合は、保存するまでワークスペースを切り替えられません。詳細画面で編集モード中に「保存する」を押した場合も一時反映で、一覧上部の「保存」で確定します。編集モード外の詳細画面の「保存する」はその場で確定します。

売上・コストが0円の場合、入力欄を開くと0を消した空欄から入力できます。詳細画面でも金額欄にフォーカスすると初期値0を消します。空欄のまま確定した場合は0円として扱い、Escでは元の値に戻します。

日付（記入日・契約予定日／締結日・入金日）は `20261105` の8桁で入力すると `2026年11月5日` と表示します。全角入力・ハイフン形式・日本語形式にも対応します。存在しない日付はエラーになり、保存しません。保存データと集計用の日付は引き続きYYYY-MM-DD形式です。
